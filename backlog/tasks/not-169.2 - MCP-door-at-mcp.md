## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
An MCP client holding an API key can initialize, list tools and call them over Streamable HTTP at /mcp, using the MCP server that ships with Effect 4 (no new dependency). One tool per typed operation, named by operationId, input schema from its Schema. See NOT-169.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 initialize, tools/list and tools/call work over HTTP with a Bearer API key; no key or a cookie session is refused
- [x] #2 A read key lists only read tools, and calling a write tool with it is refused
- [x] #3 Malformed tool arguments are a validation error naming the field
- [x] #4 A tool result equals the REST response for the same operation
- [x] #5 A page the key owner cannot read is not readable through MCP
- [x] #6 The one /mcp endpoint serves protocols 2026-07-28 (stateless), 2025-11-25 and 2025-06-18; the test covers both the stateless flow and the initialize/session flow
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Decisions (architect, 2026-10-29): a read key calling a hidden write tool gets MCP 'tool not found' (-32602) — acceptable refusal. Tools are filtered per key via the EnabledWhen annotation reading the principal with Fiber.getCurrent(); pinned by the read-key tools/list test (Effect is pinned at 4.0.0). Auth: new Bearer-only resolveApiKey(req) → { userId, keyId, scope } | AuthError; REST's resolveApiUser is rebuilt on it. Research and probes: /tmp/notara-spec/mcp-notes.md, /tmp/notara-spec/probe/, /tmp/notara-spec/probe2/.
