## Execution notes (post-review)

- **Gallery view dropped during execution.** A gallery without cover images is
  redundant with Board/Table, and Notara's database model has no image/file field
  type — a real cover would need the record's linked-page first image block (a
  per-record fetch). Deferred until that's worth building. Calendar shipped alone.
- A follow-up commit added `name` attributes to ~55 form controls across
  `packages/app` (fixes the Chrome "form field has neither id nor name" warning —
  pre-existing, unrelated to this feature, fixed on request).
- **Bug fixed + browser-verified:** switching Board→Calendar flashed then reverted
  to Board. Root cause: BoardView's toggle called bare `setViewType` without
  persisting to `localStorage`, so the view-sync effect (re-triggered by
  ViewSwitcher's `loadDbViews` on remount) read stale `localStorage` and reset.
  Fix: a single `changeViewType` handler in `DatabaseView.tsx` that always persists,
  passed to every toolbar. Reproduced and confirmed fixed via Chrome DevTools.

  Real bug, already tracked as known debt; it's a correctness fix, not a direction
  item. Flag if it surfaces while working on import-adjacent code.
